## 1. Core Assumptions & System Policies

As requested in the assessment requirements, key assumptions and data policies are explicitly documented below:

1. **Unique Measurement Identity:**
   A unique reading is identified by the natural composite key of `(device_id, timestamp)`.

2. **Duplicate & Conflicting Submissions (First-Write-Wins):**
   Physical telemetry recorded at an instant in time is immutable. 
   - **Identical Retries:** If a packet arrives with the same `(device_id, timestamp)` and identical sensor values, it is treated as a safe network retry. The server acknowledges it with `200 OK` without creating duplicate database rows (Idempotency).
   - **Conflicting Values:** If a packet arrives with the same timestamp but different sensor readings, the original measurement is preserved and the new submission is rejected with `409 Conflict`.

3. **Authoritative Event-Time & Out-of-Order Handling:**
   The hardware timestamp generated by the device is authoritative. The server's arrival time (`received_at`) is kept only for latency auditing. Late-arriving packets (e.g. from offline buffer flushes) are automatically indexed into their chronological position in the database B-Tree index `(device_id, -timestamp)`.

4. **Input Boundaries & Timezone Enforcement:**
   - **Timezone Mandatory:** Every timestamp must explicitly include timezone information (`Z` or numeric offset like `+06:00`). Missing timezones return `400 Bad Request`.
   - **Uninitialized RTC Rejection:** Clocks that revert to Epoch 1970 (`timestamp <= 0`) are rejected as hardware errors (`400 Bad Request`).
   - **Physical Limits:** Air and leaf temperatures must fall within -40.0°C to 85.0°C. Soil moisture must fall within 0.0% to 100.0%. Out-of-bounds readings return `400 Bad Request`.

5. **Floating-Point Comparison Precision:**
   To prevent false conflicts from IEEE 754 precision drift during duplicate checks, telemetry floats are compared after rounding to two decimal places (`round(val, 2)`).

6. **Agronomic Warning Rules:**
   - **Low Soil Moisture:** Triggered when the latest reading has `soil_moisture < 20.0%`.
   - **Heat Stress:** Triggered when leaf temperature $\ge$ air temperature $+ 4.0^\circ\text{C}$ in **both** of the two most recent readings (ordered chronologically by timestamp). Fewer than two readings cannot establish heat stress.
   - **Simultaneous Warnings:** Both warnings evaluate independently and can appear together.

7. **History Query Limits:**
   To protect server memory, `GET /api/devices/{id}/history/` defaults to 100 records if `?limit` is omitted, and strictly caps requests at 1000 records.

## 2. Quickstart & Installation

The application runs locally without any paid services or external database servers (uses Python's built-in SQLite).

### Prerequisites
- Python 3.10+
- C Compiler (`gcc`, `clang`, or MinGW on Windows)

---

### macOS & Linux

```bash
# 1. Clone repository and enter project
git clone <repo-url>
cd CredoSense-Assessment

# 2. Set up virtual environment and install dependencies
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. Configure environment and run database migrations
cp .env.example .env
python manage.py migrate

# 4. Run automated test suite (13 test suites / 36 test vectors)
python manage.py test

# 5. Start development server
python manage.py runserver
```

---

## 3. Running the C Edge Simulator (Option A)

The C simulator (`simulator/simulator.c`) generates deterministic telemetry covering all 5 assessment requirements: normal readings, late readings, duplicate readings, warning conditions, and invalid data.

In a separate terminal (while Django is running):

```bash
cd simulator

# Compile and generate telemetry_stream.json
make run

# Dispatch telemetry to Django backend via Python bridge
python3 bridge.py
```

## 4. API Endpoints & Example Requests

Base URL: `http://127.0.0.1:8000/api/`

### 1. Ingest Measurement
- **Endpoint:** `POST /api/measurements/`
- **Headers:** `Content-Type: application/json`

```bash
curl -X POST http://127.0.0.1:8000/api/measurements/ \
  -H "Content-Type: application/json" \
  -d '{
    "device_id": "sensor-node-01",
    "timestamp": "2026-11-07T08:00:00Z",
    "air_temperature": 24.5,
    "leaf_temperature": 29.0,
    "soil_moisture": 18.5
  }'
```

**Responses:**
- `201 Created`: Telemetry successfully validated and stored.
- `200 OK`: Telemetry already recorded with identical values (idempotent retry).
- `409 Conflict`: Telemetry timestamp already recorded with different values (First-Write-Wins).
- `400 Bad Request`: Validation failure (missing timezone, out-of-range sensor values, uninitialized RTC).

## 5. Automated Tests

The test suite is structured as a modular package (`monitoring/tests/`) with 13 test methods executing and asserting all **36 test vectors** defined in [`docs/TEST_SPECIFICATION.md`](file:///Users/shajninhaqueaishy/AI-Work/CredoSense-Assessment/docs/TEST_SPECIFICATION.md) (leveraging Python's standard library `self.subTest()` for table-driven edge verification):

```bash
python manage.py test
```

### Verified Test Categories:
- ✅ **Category A: Timestamp & RTC Boundaries (`TS-01` to `TS-07`):** UTC Zulu, timezone offsets (`+06:00`, `-05:00`), uninitialized RTC rejection (Epoch 1970, pre-epoch), naive and malformed timestamp rejection.
- ✅ **Category B: Soil Moisture Boundaries (`SM-01` to `SM-08`):** Exact lower ($0.0\%$) and upper ($100.0\%$) limits, negative and short-circuit rejection ($-0.1\%, 100.1\%, 150.0\%$), and alert threshold boundary ($19.9\%$ vs $20.0\%$).
- ✅ **Category C: Air Temperature Envelope (`AT-01` to `AT-06`):** Operational limits ($-40.0^\circ\text{C}$ to $85.0^\circ\text{C}$), sub-zero disconnects ($-55.0^\circ\text{C}$), and probe burnout rejection ($95.0^\circ\text{C}$).
- ✅ **Category D: Heat Stress & Multi-Warning (`HS-01` to `HS-04`):** Streak requirements (1 reading insufficient; 2 consecutive readings trigger warning), streak breaker ($+3.9^\circ\text{C}$), and simultaneous independent alerts.
- ✅ **Category E: Network Reliability & Concurrency (`NW-01` to `NW-05`):** Idempotent network retries (`200 OK`), conflicting duplicate rejection (`409 Conflict`), out-of-order B-Tree chronological re-indexing, concurrent `IntegrityError` conflict recovery, and IEEE 754 float rounding.
- ✅ **Category F: Schema Integrity & Query Guards (`SC-01` to `SC-06`):** Empty and missing field rejection, non-numeric type validation, multi-device data isolation, 404 handling, and history pagination limits (`?limit=N`).
